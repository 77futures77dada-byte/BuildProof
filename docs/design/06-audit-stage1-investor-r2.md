## HIGH

### 1. HIGH — «Пригласить ещё раз» и повторный вход рабочего упираются в `email_unavailable`
**Где:** §3.2 шаг 4 и §5.3 (главное действие на днях 3–7+ — «Пригласить ещё раз»), §3.4 таблица шаг 2
(«Другой браузер → … → новое приглашение»), §0.3 последний пункт, `critique-table.md` 1.5б («Без паролей верно для рабочего»).

`api/invite.ts` вызывает `admin.auth.admin.inviteUserByEmail`. Для уже существующего пользователя Supabase
отвечает «already registered», и API возвращает `409 email_unavailable` (`api/invite.ts`, блок после `inviteUserByEmail`).
Получается:
- главное действие владельца для молчащего объекта не работает для того, кого он уже пригласил. А это ровно тот случай,
  когда кнопка нужна;
- у рабочего нет пароля. Если он потерял сессию, войти он не может, а пригласить его снова нельзя. Это стена, а не задержка;
- сессию легко потерять. Ссылку из письма часто открывает встроенный браузер почтового приложения, и сессия остаётся там.
  На iOS сайт, добавленный на главный экран, хранит данные отдельно от Safari. Значит, подсказка «Добавьте на главный экран»
  из §3.4 шаг 2 сама выведет рабочего из системы;
- ссылка-приглашение одноразовая и с ограниченным сроком. Рабочий, который открыл письмо через день, может попасть
  на просроченную ссылку и не иметь второй попытки;
- каждая неудачная попытка уже записана в `invite_log` (`reserve_company_invite` выполняется до `inviteUserByEmail`)
  и съедает лимит 20 в час.

Итог: продукт обещает «вход без пароля» и при этом не даёт рабочему способа войти второй раз.

**Исправление:**
- На `/login` добавить «Войти по ссылке на почту»: `supabase.auth.signInWithOtp({ email, options: { shouldCreateUser: false, emailRedirectTo: SITE_URL + '/login' } })`.
  Это есть в Supabase Auth, бэкенд менять не нужно.
- «Пригласить ещё раз» для уже существующего человека отправляет такую же ссылку для входа, а не вызывает `api/invite.ts`.
  Ответ `email_unavailable` в UI означает «уже приглашён — отправить ссылку для входа?». Он не значит «почта занята».
- Подсказку «Добавьте на главный экран» на iOS не показывать, пока на стенде не проверено, что сессия переживает переход.
- В §3.4 шаг 2 переписать цену ошибки на «потерял сессию → входит по ссылке на почту». В `critique-table.md` 1.5б написать:
  «без паролей — только вместе со входом по ссылке на почту».
- Нужны ли Codex повторная отправка приглашения или ссылка входа от имени владельца — внести в §6 новым конфликтом ранга А.

### 2. HIGH — Весь путь активации стоит на почте, которую никто не проверил, и запасного пути нет

## MED

### 4. MED — SQL активации склеивает разных рабочих и не запускается как есть
**Где:** §2.1, блок `sql`. Перенос из r1 п. 1.

Я сверил запрос со схемой. Таблицы и поля есть: `stage_reports.reporter_id`/`created_at`/`project_id` (`002:1–10`),
`photos.report_id` (`002:12`), `photos.uploaded_by`/`uploaded_at` (`000:55–60`). Посчитать можно. Но:
- Ветка фото делает `select distinct to_timestamp(…)` без автора. Фото двух рабочих в одном 10-минутном интервале
  дают один отчёт. Текст требует противоположного: «фото **одного автора** … одним отчётом».
- Интервалы фиксированные, а не «в пределах 10 минут». Фото в 10:09 и 10:11 одного автора дадут два отчёта.
- `:project_id` — переменная `psql`, и без кавычек `uuid` не подставится. Нужно `:'project_id'`. В SQL Editor Supabase
  такой синтаксис не работает вообще. Владелец продукта, который «считает вручную», получит ошибку.
- Запрос считает один объект. Для «первых 5 фирм» нужен свод по всем объектам с `company_id`.
- Не сказано, что запрос идёт под сервисной ролью (SQL Editor). Под пользователем RLS отрежет чужие компании.

**Исправление:** заменить запрос:
```sql
-- активация по всем объектам (приближение); запускать в SQL Editor Supabase
with w as (select id from public.profiles where role = 'worker'),
ev as (
  select sr.project_id, sr.reporter_id as who, sr.created_at as at
  from public.stage_reports sr where sr.reporter_id in (select id from w)
  union all
  select ph.project_id, ph.uploaded_by, ph.uploaded_at
  from public.photos ph where ph.report_id is null and ph.uploaded_by in (select id from w)
),
win as (
  select ev.*, p.company_id from ev join public.projects p on p.id = ev.project_id
  where ev.at < p.created_at + interval '7 days'
),
g as (
  select project_id, company_id,
    case when lag(at) over (partition by project_id, who order by at) > at - interval '10 minutes' then 0 else 1 end as is_new
  from win
)
select p.company_id, p.id as project_id, coalesce(sum(g.is_new), 0) as worker_reports_7d,
       coalesce(sum(g.is_new), 0) >= 3 as activated
from public.projects p left join g on g.project_id = p.id
group by p.company_id, p.id order by p.company_id;
```
В тексте записать: «одного автора в пределах 10 минут от его предыдущего события».

### 11. MED — Автоотправка черновика обещана без проверки на iPhone
