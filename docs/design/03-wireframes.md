## 0. Общие правила для всех экранов

### 0.1 Жёсткие ограничения (проверяются на UI-этапе)

| # | Правило | Как проверяем |
|---|---|---|
| Ж1 | Касание ≥ 48 × 48 px у всего, что нажимается (ссылки, чипы-фильтры, вкладки, переключатели, «⋯», крестик закрытия). Главная кнопка ≥ 56 px. Между соседними целями ≥ 8 px, между «Подтвердить» и «Вернуть» ≥ 16 px | DOM: `getBoundingClientRect` всех `a, button, [role=button], input, select, summary, label[for]` |
| Ж2 | Текст ≥ 17 px по таблице ролей `02-type.md` §6.1. На маршрутах рабочего и бригадира вес 400 запрещён; цифры ≥ 600. `--muted` и вес 400 — только длинный текст владельца на ≥ 1024 px | computed style |
| Ж3 | Статус = SVG-значок + слово. Цвет никогда не единственный признак. Символы `○ ✓ → ● ✗ ▲` в строках интерфейса запрещены (regex `02-type.md` §8) | `check-ru-latin` + regex по `src/**` |
| Ж4 | Одна главная (жёлтая, `--accent`) кнопка на экран или ни одной. Двух жёлтых блоков подряд нет. Плашка «не отправлено» — свой токен `--unsent-*`, не жёлтый | DOM: счёт `[data-main]` ≤ 1 в видимой области экрана |
| Ж5 | Sticky «Отправить» листа отчёта видна без прокрутки на 360 × 640 и 375 × 667 во всех состояниях (рост, снижение с причинами, пауза, скачок, черновики) | Playwright, 2 размера × 5 состояний |
| Ж6 | Нет горизонтального скролла страницы на 360, 390, 768, 1024, 1440. Внутренний скролл полосы вкладок владельца разрешён (см. §2.2) | `scripts/check-overflow.mjs` |
| Ж7 | Тема одна: токены на `:root` (`tokens.css`), тёмная по системе + `data-theme`. Ни один экран, лист или модалка не выпадает из темы | сравнение computed `--bg`/`font-family` по всем `id` |
| Ж8 | **Все модалки и листы рендерятся внутри корня темы.** Портал `Modal` монтируется не в голый `document.body`, а в контейнер `#bp-portal` внутри корня с токенами (или токены живут на `:root`, тогда портал в `body` наследует их). Оверлей — токен `--scrim`, не `bg-black/75`. Фокус уходит в диалог и возвращается на кнопку-источник; `Esc` и «Закрыть» (≥ 48 px) — всегда | DOM: у `[role=dialog]` computed `font-family` = Onest, `color` = `--fg` |
| Ж9 | Тупиков нет: у каждого экрана есть путь вперёд (главное действие или следующий шаг) и путь назад (шапка, «Назад», вкладка или ссылка «К объектам») | таблица навигации §1 |
| Ж10 | Загрузка без пустого экрана: `Suspense fallback={null}` заменяется на `app-loading` (логотип + спиннер в теме) | визуально + DOM |

### 0.2 Словарь состояний (одинаков в `.md` и `.json`)

| id состояния | Что значит | Как выглядит (общая форма) |
|---|---|---|
| `loading` | данные грузятся | скелет блоков в их будущих размерах (не прыгает), подпись `copy:common.loading` |
| `error` | запрос не прошёл (не сеть) | блок `ErrorBlock`: SVG `stale` + короткий текст + «Попробовать ещё раз» (вторичная кнопка). Текст сервера не показываем |
| `offline` | `navigator.onLine === false` или таймаут сети | полоса `NetBar` вверху контента: «Нет сети» `copy:common.offline*`. Данные, что уже на экране, остаются. Отправка форм неактивна с подписью, кроме листа отчёта (он пишет черновик) |
| `empty` | данных нет, и это нормально | `EmptyState`: что здесь будет + **следующее действие и кто его делает** (бриф 2.1.7) |
| `no-reports` | у объекта/этапа нет ни одного отчёта | значок `none` (пунктирное кольцо, см. §11 П10) + «Отчётов нет» + следующий шаг. Не красный, не «всё хорошо» |
| `accepted` | отчёт засчитан без проверки (≤ 25 п.) | **до K15:** чип «Отмечено бригадой» `copy:status.marked*` без значка `ok`; **после K15:** «Принято» `copy:status.accepted*` |
| `pending` | скачок > 25, ждёт проверки | **только после K15.** До K15: строка «крупный скачок +N, не проверен» `copy:status.bigJump*` (SVG `pending`) |
| `confirmed` | проверено бригадиром/владельцем | **только после K15/K32.** Чип «Проверено», SVG `ok` (галочка в залитом круге). `ok` нигде больше не используется |
| `unsent` | есть черновики `queued`/`unknown` | `UnsentBanner` вместо главной кнопки (`02-type.md` §6.2) |
| `stale-draft` | черновик устарел (`stale`) | карточка решения в листе: «Не принято: этап уже N%» + «Отправить с новым %» (главная) / «Удалить» |
| `paused` | `projects.status = paused` | чип «На паузе» (SVG `paused`), без цвета свежести, объект ниже активных |
| `completed` | `projects.status = completed` | чип «Завершён» (SVG `done-flag`), ниже паузы |
| `gate-closed` | `VITE_EMAIL_GATE_OPEN` ≠ `true` | нет кнопок «Пригласить», «Войти по коду», «Забыли пароль?», «Отправить код входа», «Регистрация» |
| `gate-open` | флаг включён | эти кнопки есть |
| `legal-empty` / `legal-filled` | `src/config/legal.ts` пуст / заполнен | контакт основателя в тупиках и «Написать о продолжении» — только при `legal-filled`; иначе блок **скрыт целиком**, без плейсхолдеров |
| `k15-off` / `k15-on` | флаг сборки на статусы отчётов (появятся поля `stage_reports`) | см. `accepted`/`pending`/`confirmed`. Очередь проверки скрыта при `k15-off` |

Флаг `k15-on` — предложение (имя `VITE_REPORT_REVIEW`*); UI-этап может заменить на проверку наличия полей. Важно одно: «Принято / Ждёт проверки / Проверено» не появляются раньше бэкенда (остаток И4-М2).

### 0.3 Сетка

- **Мобильный (база 390, проверка 360):** одна колонка, поля 16 px, ширина контента 358 (328 на 360). Шапка 56 px. Нижняя безопасная зона учитывается у sticky-кнопок (`env(safe-area-inset-bottom)`).
- **Планшет 768:** одна колонка, `max-width: 720`.
- **Десктоп ≥ 1024:** контейнер 1120; список объектов — плотные строки; обзор объекта — две колонки 7/5 (слева главное и этапы, справа люди и лента); листы — центрированный диалог `max-width: 560`, высота ≤ 90 vh.
- **1440:** тот же контейнер 1120 по центру, ничего не растягивается.

## 1. Карта навигации

```
/  (лендинг, отдельный PR)
 ├─ «Войти» ─────────────────────────────► /login
 └─ #start регистрация (шлюз) ──created──► /dashboard

/login  [login-password | login-code-request | login-code-enter | login-invite-code | login-link-error]
 └─ сессия есть ─► маршрут по роли (остаток М4-7):
       gc ─────────────► /dashboard
       foreman/client ─► /dashboard (1 объект → /project/:id)
       worker ─────────► 1 объект → /project/:id/today; иначе /dashboard (выбор объекта)
       профиля нет ────► создание компании на /dashboard → ошибка → profile-not-configured

/dashboard (gc) ─ карточка ─► /project/:id
              ├─ «Создать объект» ─► create-project ─► /project/:id (день 0)
              ├─ «Тариф» (шапка) ─► /tariff ─► «К объектам» ─► /dashboard
              └─ «Проверить N» (k15-on) ─► /review

/project/:id (шапка: «К объектам» = логотип, вкладки)
 ├─ Обзор ── «Отметить первый этап» ─► report-sheet (этап 1)
 │        ├─ «Пригласить рабочего» (шлюз) ─► /project/:id/people#invite
 │        ├─ «Открыть людей объекта» (3+ дня) ─► /project/:id/people
 │        ├─ «Открыть последний отчёт» ─► photo-viewer (отчёт)
 │        └─ «⋯» ─► pause/complete confirm
 ├─ Этапы ── строка этапа ─► report-sheet
 ├─ Фото ─── «Сфотографировать» ─► камера ─► report-sheet; плитка ─► photo-viewer
 ├─ Задачи ─ «Новая задача» ─► task-form; «Готово» у задачи с этапом ─► report-sheet
 ├─ Проблемы ─ «Сообщить о проблеме» ─► issue-form; фото ─► issue-photo-zoom
 └─ Люди (gc) ─ «Добавить на объект», «Пригласить (N)», «Отправить код входа» ─► send-login-code

/project/:id/today (worker) ─ «Сфотографировать: {этап}» ─► камера ─► report-sheet ─► today
                           └─ плашка «не отправлено» ─ «Отправить снова»

/review (k15-on) ─ строка ─ «Подтвердить» / «Вернуть» ─► undo-bar ─ уход с экрана ─► /dashboard
/tariff ─► /dashboard
*  (404) ─► сессия есть: /dashboard; нет: /login и «/»
```

Правило «назад»: в оболочке проекта назад = логотип/«К объектам» (`/dashboard`); для рабочего с одним объектом логотип ведёт на `today` (у него нет списка). Лист и модалка закрываются «Закрыть»/`Esc`/жестом назад браузера (лист добавляет запись в `history`, чтобы системная «назад» на Android закрывала лист, а не уходила со страницы). Лист с несохранённым снимком при закрытии **не теряет снимок**: черновик `editing` уже записан (01 §3.4 п.1).

## 2. Оболочки

### 2.1 `shell-app` — шапка вне объекта (`/dashboard`, `/tariff`, `/review`)

Блоки: логотип (ссылка на `/dashboard`, ≥ 48 px) · справа: «Тариф» (только gc) · переключатель языка (≥ 48 px) · «Выйти».
- «Выйти» при наличии черновиков текущего пользователя → `signout-drafts-confirm`.
- Имя и роль: на ≥ 1024 справа от логотипа, 17 px; на мобильном не показываем.
- Роли в подписи: «Владелец / Бригадир / Рабочий / Заказчик» (`copy:roles.*` переписываются: не «Генподрядчик», не «Прораб»).

### 2.2 `shell-project` — оболочка `/project/:id/*`

Блоки по важности:
1. Шапка: логотип/«К объектам» · язык · «Выйти». (Рабочий с одним объектом: логотип → `today`.)
2. Название объекта (заголовок экрана 22–28 px) + чип статуса объекта, только если не «активный» (`paused`/`completed`). Адрес — вторичная строка 17 px.
3. Полоса вкладок:
   - **gc:** Обзор · Этапы · Фото · Задачи · Проблемы · Люди (бывшие «Настройки»);
   - **foreman:** Обзор · Этапы · Фото · Задачи · Проблемы;
   - **client:** Обзор · Этапы · Фото · Проблемы (Задачи у заказчика скрыть — внутренняя кухня; вопрос В3);
   - **worker:** Сегодня · Этапы · Фото · Проблемы, растянуты на ширину.
   Вкладка 17 px / 600, касание ≥ 48 px, активная — `--fg` + полоса 3 px. У владельца 6 вкладок на 360 не помещаются: полоса скроллится **внутри себя** (страница не скроллится), активная вкладка прокручивается в видимую область, справа градиент-намёк. На ≥ 768 все вкладки видны.
4. Контент `Outlet`.

Состояния оболочки: `loading` (скелет шапки, вкладки уже видны — они от роли, не от данных), `error` (объект не найден или нет доступа → `ErrorBlock` «Нет доступа к объекту» + «К объектам»; не 404 и не пустой экран), `paused`, `completed`.

Тёмная тема одинакова на всех вкладках (сейчас — только на Обзоре, `ProjectLayout.tsx:57`). `data-skin-dark` уходит.

## 3. Вход и системные экраны

### 3.1 `login-password` — `/login`, пароль (шлюз закрыт и открыт)
- **Роли:** все (гость).
- **Главная кнопка:** «Войти» `copy:common.signIn`.
- **Блоки (390):**
  1. Логотип + одна строка, что это (`copy:auth.tagline`, без «и заказчика» — остаток И4-HIGH).
  2. Поле «Почта» `copy:auth.email` (не «Email»), `autocomplete=email`, 56 px.
  3. Поле «Пароль», показать/скрыть (≥ 48 px).
  4. Ошибка под полями (17 px / 600, SVG `stale`).
  5. **Главная «Войти»** во всю ширину.
  6. Шлюз открыт: вторично «Войти по коду из письма» → `login-code-request`; «Забыли пароль?» → `login-code-request` с режимом сброса. Шлюз закрыт: вместо них строка `copy:auth.recoveryLater*` «Восстановление по почте включится после настройки почты» + контакт `LEGAL.phone/email` только при `legal-filled`.
  7. «У меня есть код из приглашения» → `login-invite-code` (только шлюз открыт; остаток Б4-HIGH).
  8. Строка черновиков, если в IndexedDB есть неотправленные: «N отчётов ждут отправки» (`copy:auth.draftsWaiting*`, только число).
  9. Низ: «Нет аккаунта? Начать бесплатно» → `/#start` **только при `gate-open`** (остаток М4-1); при закрытом — `copy:auth.signupLater*` + контакт при `legal-filled`. «На главную» `copy:auth.backHome` (≥ 48 px, сейчас 44), язык.
- **Десктоп:** карточка 420 px по центру; слева ничего не добавляем (без иллюстраций).
- **Состояния:** `loading` (сессия проверяется → `app-loading`), `submitting` (кнопка в спиннере, поля неактивны), `error-credentials` (`copy:auth.invalidCredentials`), `error-not-confirmed`, `error-rate`, `offline` (`copy:auth.network`), `gate-closed`, `gate-open`, `drafts-waiting`, `legal-empty/filled`, `hash-error` (в URL `#error=` → сразу `login-link-error`).
- **Навигация:** из лендинга, 404, редиректа `ProtectedRoute` (сохраняем `from`), выхода. Вперёд — маршрут по роли (§1). Назад — «На главную».

### 3.2 `login-code-request` — `/login?mode=code` (только шлюз открыт)
- **Главная:** «Прислать код на p•••@gmail.com» (если почта запомнена, `bp:lastEmail`) или «Прислать код» после ввода почты.
- **Блоки:** заголовок · (запомнена почта) маска почты + вторично «Другая почта» / (нет) поле «Почта» · главная · «Войти по паролю» · строка черновиков.
- **Состояния (таблица 01 §0.3):** `sending`; `sent` → переход в `login-code-enter`; `rate-address` «Новый код можно через N с» (обратный отсчёт, кнопка неактивна); `rate-project` «Сейчас письма не уходят. Попробуйте позже» (без «отправлено»); `unknown-address` — нейтрально «Если адрес есть в BuildProof, код придёт» и всё равно переход в ввод кода; `offline`/`error` «Не отправлено. Попробовать ещё раз». Режим сброса пароля — тот же экран, заголовок другой (`copy:auth.resetTitle*`).
- **Навигация:** из `login-password`, `login-link-error`, листа отчёта (`authentication_required`), `send-login-code`-письма. Назад — «Войти по паролю».

### 3.3 `login-code-enter` — `/login?mode=code&step=enter`
- **Главная:** «Войти».
- **Блоки:** «Код отправлен на {почта}. Через минуту проверьте «Спам»» · поле кода (одно поле, `inputmode=numeric`, `autocomplete=one-time-code`, **6–10 цифр**, вставка из буфера, 20 px / 600 без tnum, `letter-spacing .08em`) · главная · «Прислать снова» (неактивна 60 с, отсчёт в тексте) · «Другая почта».
- **Состояние «код отправлен на {почта}» хранится в `sessionStorage`** (остаток Б4-М5): ушёл в почту и вернулся — экран тот же, отсчёт продолжается.
- **Состояния:** `idle`, `verifying`, `wrong-code` «Код не подошёл» (поле не очищаем), `expired` → `login-link-error`, `resend-countdown`, `offline`.
- **Бюджет касаний** (пишем отдельно, остаток Б4-М5): iOS — «Прислать код на p•••» → открыть Почту → письмо → подсказка кода над клавиатурой (если почта Apple) или копировать → вернуться → вставить → «Войти» ≈ 6; Android (Gmail) — «Прислать код» → уведомление → копировать код из уведомления → вернуться → вставить → «Войти» ≈ 5. Цель 01 «≈ 5» достижима только на Android.

### 3.4 `login-invite-code` — `/login?mode=invite` (шлюз открыт)
- **Главная:** «Войти» (`verifyOtp({email, token, type:'invite'})`).
- **Блоки:** заголовок `copy:auth.inviteTitle*` · поле «Почта, на которую пришло приглашение» · поле кода (как в 3.3) · главная · подсказка «Ссылку из письма лучше открывать в Safari или Chrome» · «Войти по паролю».
- **Состояния:** `idle`, `verifying`, `wrong-code`, `expired` → `login-link-error`, `offline`.
- **После успеха:** бригадир → `auth-set-password`; рабочий → `today` (по роли).

### 3.5 `login-link-error` — `/login#error=…` (`otp_expired`, `access_denied`, PKCE в другом браузере)
- **Главная:** «Прислать код» (шлюз открыт). **Шлюз закрыт:** главная «Войти по паролю» (этот экран при закрытом шлюзе возможен только по старой ссылке).
- **Блоки:** SVG `stale` + «Код или ссылка устарели. Пришлём новый» · для PKCE — «Откройте ссылку в том браузере, где просили, или введите код» · главная · «Ввести код» → `login-code-enter` · «Войти по паролю».
- **Навигация:** из письма. Тупика нет: всегда два пути.

### 3.6 `auth-set-password` — после первого входа по приглашению (бригадир; шлюз открыт)
- **Главная:** «Сохранить пароль» (01 §3.3 п.1). Экрана в коде нет — новый.

### 6.2 `report-sheet` — лист отчёта (рабочий, бригадир, владелец)
Полноэкранный лист на мобильном (не модалка поверх контента), диалог 560 на десктопе. Рендерится в корне темы (Ж8). Открывается **после снимка** (камера сразу), из `today`, `stages`, `photos`, «Готово» у задачи, строки этапа на обзоре, «Отметить первый этап».

- **Главная:** «Отправить» (sticky внизу, ≥ 56 px, safe-area). В `stale-draft` главная — «Отправить с новым %».
- **Порядок блоков фиксирован** (01 §3.4, DOM-проверка на UI-этапе), 360 × 640:

| # | Блок | Высота на 360 × 640 |
|---|---|---|
| — | шапка листа: «Закрыть» (48) · заголовок «Отчёт» | 56 |
| 1 | «{объект} · {имя}» одной строкой, обрезка | 28 |
| 2 | миниатюра ≤ 25 % высоты (≤ 160), касание — «Переснять» | ≤ 160 |
| 3 | «было N% [стрелка SVG] станет M%» (M 32/700) | 48 |
| 4 | кнопки «−10» «+10» «+25» «Готово 100%» — один ряд по 4 на ≥ 360 (по 74 px), ≥ 56 px; в пределах 0–100; по умолчанию «без изменений» | 56 |
| 5 | «Этап: {имя} · Сменить» (ссылка ≥ 48) | 48 |
| 6 | причины снижения — только при M < N: 3 чипа (`rework`/`count_error`/`demolition`) в 2 ряда | 0 / 112 |
| 7 | плашки по одной строке: пауза, «Большой шаг. Владелец посмотрит фото» (скачок > 25, 17 px, ≥ 7:1), черновики | 0–3 × 40 |
| — | sticky «Отправить» + отступ | 56 + 16 + safe |

Сумма худшего случая (снижение + пауза + черновик): 56 + 28 + 160 + 48 + 56 + 48 + 112 + 120 + 72 = 700 > 640 → **миниатюра сжимается до 15 % (96 px) при показе причин**, остальное прокручивается **под** sticky-кнопкой; кнопка видна всегда (Ж5). Кнопка неактивна, пока не выбрана причина при снижении (подпись над кнопкой «Выберите причину»).

- **Состояния листа:** `editing` (снимок есть, черновик `editing` записан), `no-change` (только фото — разрешено), `increase`, `decrease-needs-reason`, `big-jump` (> 25), `paused`, `sending` (SVG `sending` + «Отправляется», кнопка неактивна), `sent` (лист закрывается, на экране-источнике `SendStateRow` «Отправлено» с SVG `sent` — **не** галочка `ok`), `unknown` (20 с без ответа: «Нет сети — проверим, когда появится»), `queued` («Сохранено на телефоне, не отправлено.
